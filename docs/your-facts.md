# Your facts file

Your facts file is a private record of your career that you can reuse across applications. Keep it broader than any single CV: a qualification omitted from one application may matter to the next employer.

## Create it from your existing CV

Provide a CV or career notes and choose where the structured file should live. In this checkout, use a path under ignored `private/`, such as `private/my-facts.json`. Ask the agent to extract the facts, retain their sources and show you what needs clarification.

You can also start with the [blank template](../skills/targeted-cv/templates/cv-facts.blank.json). It contains empty fields rather than a candidate's details. You do not have to invent values to complete it. If you already have a facts file in an older format, ask the agent to check it before proposing a migration.

## What belongs in the file

Keep contact details, employment history, education, qualifications, projects, languages and relevant skills. Include evidence that helps explain what you did: responsibility, scope, decisions, results and when the work happened. Record sources and uncertainty so later wording can stay accurate.

Distinguish personal authority from organizational context. Advising on a decision is different from approving it. Working with a team does not necessarily mean managing its members. Earlier programming experience does not establish current hands-on proficiency.

Known education and certification dates can remain in the file even when you choose not to show them in a CV. Completion, expiry and renewal are different facts. Keep the full qualification inventory and select relevant entries for each application.

## What belongs to an application instead

| Reusable facts | Application choices |
| --- | --- |
| Actual employment title and responsibilities | Target-role headline and positioning |
| Qualifications and their recorded status | Which qualifications to include |
| Supported achievements and scope | Which examples address this offer |
| Original evidence and confirmed corrections | Language, country, offer, drafts and review notes |

A job offer is not evidence about you. The agent must ask before treating an attractive requirement as a qualification you possess.

## Review and correct your facts

Confirm extracted details and correct mistakes before relying on them in an application. You can leave a detail unknown, skip a question or state that it does not apply. These answers have different meanings.

When a conversation reveals a reusable correction, the agent proposes an update to the facts file. Review that change separately from wording changes to the current CV. The workflow retains the previous version and confirms that the saved file contains the intended correction before using it as the new source.

For bilingual applications, use one facts file. Translations may change phrasing, but must preserve the same qualifications, dates, responsibility and results.

## Keep it private

Do not put a completed facts file in the skill's templates or test fixtures. Keep personal sources and derived drafts private too. Sharing the skill should not share your profile. The [privacy policy](../.kiro/steering/privacy.md) explains the repository boundary; the [workflow guide](application-workflow.md) explains how to use your facts for an application.
