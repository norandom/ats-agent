# Release acceptance scenarios

This is the maintenance test closure, not an installed application runtime. Core hashes include every reference, schema and the blank template. The retained upstream runners require their explicitly selected private evidence where declared; relocation results do not prove standalone installation.

All 44 criteria are mapped to approved implementation tasks with `not_assessed` status. Mapping is a plan, never a passing receipt. Later work must bind executed results to the selected archive, installation and independently reviewed evidence index.

- `actual`: directly observed host, filesystem, build or WordCraft operation.
- `control`: deterministic adverse or positive test of a contract; cannot stand in for a live document operation.
- `host_judgment`: competent source-meaning, privacy or page review, recorded separately from mechanical checks.

The foundation suite verifies complete generic closure, criterion coverage, preserved core bytes and truthful prerequisite reporting. Missing tools remain unassessed; no endpoint, API key, document service or background application is started.

Use `pnpm exec node --test tests/portable-skill-release/foundation.test.cjs` for focused checks. Use `pnpm exec node tests/portable-skill-release/foundation.cjs` for inventory verification and add `--probe` for bounded local tool observations. On Windows invoke `pnpm.exe` from PowerShell. On Linux use Bash. Probe output contains version/status fields, not command output or local tool paths. Dagger, ZIP and upstream test runners are maintainer tooling; the pinned uvx validator and trusted execution/file capabilities belong to applicant prerequisites. External Node/pnpm is a runtime requirement only for a selected host that needs it.
