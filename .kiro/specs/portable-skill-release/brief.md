# Brief: portable-skill-release

## Problem
The completed workflow must be shareable without the author's data, machine paths, sibling checkout or obsolete Python scoring application.

## Current State
This is a new milestone boundary split from the initialized targeted-cv-skill umbrella. Shared research and user decisions remain in that directory. A candidate schema and blank template already exist as preliminary inputs; the legacy Python scorer is still present. No milestone implementation or phase approval is implied.

## Desired Outcome
A separately maintained, installable skill package works for a new candidate and replaces the legacy Python workflow.

## Approach
Deliver M5 scope as a reusable skill capability, governed by project steering. Use the existing evidence/source register and user-confirmed decisions. Specify observable contracts before implementation; preserve judgment in persuasive writing and explicit invariants in data handling.

## Scope
### In

- Use versioned packaging/manifest conventions from ../Skills while keeping this repository independent.
- Explicit package allowlist and archive inspection; exclude private/examples/outputs, source PDFs, credentials and local configurations.
- Verify dependency declarations, uv/uvx setup and actual WordCraft requirements on a clean installation.
- Provide synthetic end-to-end examples and run profile-to-offer-to-live-document acceptance checks.
- Retire legacy Python application/dependencies/examples and update project instructions once replacement acceptance passes.
- Prepare local release artifacts; remote publication/marketplace registration is a separate action.

### Out

- New candidate analysis, document engines or scoring features.

## Milestone Acceptance Evidence
- A clean install works without ../Skills, original machine paths or candidate-specific defaults.
- Package inspection finds only permitted generic files; a second synthetic candidate completes the same flow.
- Final workflow handles both languages, Germany DIN letters, questions, scores and preserved live edits.
- Legacy Python removal occurs only after the replacement passes required checks; no active documentation points at removed entrypoints.
- Package licenses and redistribution rights are checked for included materials; private references remain outside the archive.

## Open Design Investigations
- Adapt the smallest useful ecosystem packaging pieces; choose package identity/version and declared host support.
- Determine reproducible packaging and validation commands without introducing a new Python application.

## Constraints
No personal data in committed instructions or distributable assets. German/English target output; WordCraft MCP authors final DOCX; blue/no photos; DIN 5008 letters for Germany in either language. No maintained Python application. Keep professional source support distinct from editorial judgment and user preferences. Candidate examples are synthetic and unrelated to private profiles.
