# Implementation plan

Each executable task is a 1 to 3 hour work unit, including its focused checks. Container headings are not additional work units. Tasks run sequentially: shared release records, archive destinations and the desktop session prevent safe parallel implementation. Package guidance and notices are functional distribution assets, verified with their owning capability.

## Implementation notes

- Before the next candidate version, derive the root-version test assertion from VERSION; fixed fictional record examples can retain explicit versions.

- Task 3 must resolve seven pre-existing core checkout/Git line-ending differences without silently changing the tested runtime bytes. Rights currently bind exact checkout bytes; no exact Git-blob or source-bound artifact claim has been made.
- The manifest is now an explicit mapping record. Preparation and packaging consumers still require their planned task 3 upgrades; definition validation alone does not make their older context/layout usable.

- Task 3.1 preserves payload bytes with Git attributes and selective raw-byte staging. Maintenance inputs use selected Git blobs when checkout differences are CRLF-only. Keep checkout_sha256 observations outside artifact identity; canonical build-input identity uses path, size and sha256 only.

- Task 3.4 builds raw stages on the Linux container filesystem and exports finished archives only; DrvFS modes can differ despite chmod. Keep production /source immutable, tests in /work and unique attempt IDs before validation/production to avoid reusing prior execution evidence.

- Group 4 separates collection, mechanical evidence verification and actual installed-workflow acceptance. Keep independently selected index/review digests and authenticated competent observations; a passed helper result or an old artifact's receipts do not grant readiness for a newly built artifact.

- Group 5 adds the fixed complete-validation runner and exact retirement policy. Future task 7.1 must create a dedicated retirement commit containing only the eight declared removals and five updates. Record its prior revision and diff for scoped recovery; commit task/review metadata separately. Later approved metadata may advance HEAD, while frozen B retains its own exact source and evidence bindings.
