# Default composition and language review

User direction, 2026-10-25: apply COBESY and Humanizer by default to application writing, especially expertise sections. No em dashes. This supplements the review-agent proposal without approving unfinished milestone implementations.

## Pipeline

1. Read the explicitly selected structured profile and the offer or declared role target. Add confirmed new facts through a sourced, authorized profile update, preserving the previous version. Private editorial drafts are derived artifacts, not another source of career truth.
2. Discover and read the installed COBESY skill, using its composition path. Define audience, intended decision and governing contribution. Treat employer culture as unknown without evidence; do not invent organizational psychology or a network map. For a CV, behavioral rollout analysis is not applicable.
3. Structure expertise around useful capabilities and decisions, supported by concrete experience. Put relevant frameworks and platforms in a compact secondary list. Do not let an inventory of old tools position a leadership applicant as an individual contributor. Historical tools can remain in their actual employment context without implying current proficiency.
   Treat named products as examples unless the user states they delimit responsibility. Formal education does not establish that a method is used at work. Separate commercial context, advisory responsibility, contract ownership and spending approval. Preserve active leadership when supported; do not weaken it into passive assistance or inflate influence into formal authority.
4. Use Humanizer in embedded mode on the draft. Run draft, factual audit and final rewrite internally. Preserve exact credentials, genuine employment titles, metrics and dates; no invented achievements to make the prose vivid. Remove inflated claims, boilerplate, sentence sprawl and decorative punctuation. Use no em or en dashes in submitted copy; use words for date ranges. Keep conventional CV bullets and restrained heading emphasis.
5. Compile both languages from the same facts snapshot, with language-specific wording and private source mappings. Rendering scripts accept data and style settings; they contain no candidate identity, career claims or model endpoint calls. Source-ID existence is only a structural check; the host must verify meaning against the record.
6. Inspect extracted text and every rendered page. Record which checks actually ran. A successful local extraction is not proof of universal ATS compatibility.

## Credential selection

Keep the full credential inventory in the selected private facts file. Select and order credentials against the offer's actual tasks and requirements; a general CV is only a baseline. Do not include every certificate by default or penalize an unfamiliar acronym. Where helpful, show the official full credential name and acronym together, preserving the issuer and level. Verify naming separately from possession: a public issuer page does not verify the candidate's award or current renewal status. Do not inflate a certified expert qualification into publicly appointed or sworn status. Missing award dates are not a quality defect. Preserve selection rationale in private review data and ask about current validity only when material to the target role.

## Portability

Discover skills by name, not developer-machine paths. Do not bundle the user's local skill directories without a separate redistribution review. If an installed skill is unavailable, report that limitation and use the self-contained editorial criteria here; do not claim the missing skill was executed. Release design must resolve the optional integration and version handling.

## Source-backed context

- Greenhouse's unsuccessful-resume-parse guidance lists complex layouts, columns, text boxes and unclear sections as possible parsing issues. It does not establish a universal ban on pipe characters. Plain text separators are a layout choice; test actual extraction. https://support.greenhouse.io/hc/en-us/articles/200989175-Unsuccessful-resume-parse
- CareerOneStop describes skills as optional and recommends job-relevant technical content. This supports a selective summary, not a compulsory exhaustive grid. https://cloudfront.careeronestop.org/JobSearch/Resumes/ResumeGuide/top-portion-of-resume.aspx
- COBESY and Humanizer supply editorial methods. They are not evidence for ATS ranking, hiring predictions or psychological judgments about a candidate.
