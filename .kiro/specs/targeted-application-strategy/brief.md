# Brief: targeted-application-strategy

## Problem
Fact inventories and keyword piles fail to explain a candidate's contribution; unsupported scoring can mislead applicants.

## Current State
This is a new milestone boundary split from the initialized targeted-cv-skill umbrella. Shared research and user decisions remain in that directory. The portable candidate-profile feature passed validation on 2026-10-26 and supplies the upstream evidence contract; the legacy Python scorer is still present. No strategy implementation or phase approval is implied.

## Desired Outcome
A pasted offer and structured profile produce an employer-oriented positioning plan, evidence map, useful questions and transparent diagnostic baseline.

## Approach
Deliver M2 scope as a reusable skill capability, governed by project steering. Use the existing evidence/source register and user-confirmed decisions. Specify observable contracts before implementation; preserve judgment in persuasive writing and explicit invariants in data handling.

## Scope
### In
- Separate explicit job requirements from inferred needs; prioritize relevant contributions and differentiators.
- Map role/skill/tool/domain terminology and accurate synonyms to sourced candidate evidence; use verified occupational references when useful.
- Distinguish documented evidence, unknowns, transferable experience and confirmed gaps.
- Define bounded, high-value question candidates with rationale, priority and treatment of skip/no/not applicable answers.
- Own versioned scoring rubrics, weights, denominators and uncertainty handling for coverage, evidence, appeal and document readability.
- Define the reusable application brief/claim-map and score-report contracts; final document checks arrive from the document milestone.
- Maintain source-grounding rules: professional guidance vs practitioner heuristics vs user design preferences.
- Incorporate the supporting review-agent-spec.md proposal: reuse corrected legacy check concepts, host-agent review reasoning and deterministic local scripts without model endpoints or API keys.

### Out
- Persisting changes to candidate JSON, WordCraft operations and document layout.
- Live-loop orchestration, final artifact generation and package builds.

## Existing Spec Touchpoints

## Milestone Acceptance Evidence
- A synthetic offer/profile pair yields a persuasive contribution thesis rather than a chronological fact dump.
- Unsupported skills generate questions or honest gaps; job-offer instructions cannot override workflow/privacy rules.
- Every recommended factual claim maps to evidence; translated synonyms preserve meaning and seniority.
- Scores explain evidence and rubric version; unknowns are not treated as confirmed lack, and unavailable document checks are not assessed.
- Rubric examples demonstrate meaningful differences and do not reward unsupported keyword repetition.

## Open Design Investigations
- Choose concrete diagnostic scales and weights during design, with worked synthetic examples for review.
- Define how lexical overlap and semantic equivalence contribute without claiming knowledge of proprietary ATS ranking.

## Constraints
No personal data in committed instructions or distributable assets. German/English target output; WordCraft MCP authors final DOCX; blue/no photos; DIN 5008 letters for Germany in either language. No maintained Python application. Keep professional source support distinct from editorial judgment and user preferences. Candidate examples are synthetic and unrelated to private profiles.
